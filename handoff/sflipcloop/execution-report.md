## 6. 规划 → 实际：偏离与决策记录

> 格式：原规划条目 → 实际决策 → 触发证据 → 对形体/质量/性能的影响 → 测试结果 → 剩余限制。

### 偏离 #1：各层柱顶标高与檐口标高的关系（规划未规定）

- **原规划**：§4.3 给出六重檐口标高 `[10.50, 16.00, 25.00, 34.50, 44.00, 54.10]`，但未规定柱顶标高。
- **实际**：按「柱顶 = 本层正檐标高 − 铺作高 1.1 m」反推，得各层柱顶 `14.9 / 23.9 / 33.4 / 42.9 / 53.0`，
  使铺作确实位于柱头并承托屋面。
- **触发证据**：首版实现中铺作被放在 `lv.band.y1`，屋面与铺作脱开；`getSceneInfo()` 显示第五层柱止于 52.0 而攒尖檐在 54.1，差 1.4 m。
- **影响**：塔身各层柱长分布与规划 §4.3 的「展示带」区间不再相同（展示带是 UI 讲解区间，非结构柱长）。
- **测试**：`tests/geometry.test.js` 断言逐层柱网、48 柱 / 24 柱等仍成立；比例校验器 14/14。

### 偏离 #2：裙檐（下檐）内端环落位

- **原规划**：§4.4 只说裙檐用副阶柱环，未指明屋面内端收在哪条环上。
- **实际**：内端落在**塔身外槽柱线**（`innerRingMode: 'outer'`），而非副阶柱环。
- **触发证据**：原实现把内端也放在副阶环上，使裙檐退化成 0.9 m 宽的一圈薄片；
  与 Wikimedia 实拍（`references/photos/view-02.jpg`）对照明显不符。
- **影响**：裙檐由薄片变为 3.36 m 宽的实体屋面，体量与实物一致。
- **测试**：`tests/geometry.test.js` 新增「裙檐的内端落在塔身外槽柱线上」断言；`eaveSlope()` 实测裙檐 32.0°。

### 偏离 #3：台基下层方形边长 40 m → 33 m

- **原规划**：M06 标「待核实（二次传播约 40）」，模型 E = 40。
- **实际**：改为 **33 m**，并保持「估算」标注。
- **触发证据**：40 m 方形基座的对角距达 56.6 m，远超塔身底径 30.27 m，画面上像一块巨大的空地；
  实拍显示台基仅略宽于副阶柱环。
- **影响**：台基在画面中的占比与实物接近；数值仍标「估算 / 待核实」，未冒充实测。

### 偏离 #4：光照数值上调（色板不变）

- **原规划**：§4.5 白昼半球光 2.1 / 太阳 3.2 / 曝光 0.90；夕照 1.15 / 2.4 / 0.94；夜景 0.45 / 1.1 / 1.02。
- **实际**：白昼 **2.7 / 3.6 / 1.02**；夕照 **1.4 / 2.7 / 1.04**；夜景 **0.58 / 1.1 / 1.12**。色板（#47362D 等）未动。
- **触发证据**：首版渲染中上层明层与檐下斗栱几乎全黑（`reports/screenshots` 早期版本），
  与实拍「斗栱呈风化浅褐、在阳光下可辨」明显不符。
- **影响**：暗部保留纹理、斗栱可读；夜景仍未过曝（见 `15-light-night.png`）。
- **剩余限制**：偏离规划给出的具体数值；属执行 Agent 在规划 §7 授权内的「小范围调参」。

### 偏离 #5：画质档**不重建几何**（低端档三角形数超预算）

- **原规划**：§3.3 要求低端档使用斗栱 LOD2、瓦片稀疏抽样。
- **实际**：几何在构建期一次性按高档密度生成，画质档只切换 **DPR / 阴影 / 后期**。
- **触发证据**：运行时重建几何需重做全部实例池，复杂度与收益不匹配；
  且实测低端档已达 59.88 FPS。
- **影响**：低端档 draw call 60（目标 < 130 ✅），但**三角形 270 440（目标 < 120 000 ✗）**；「中」档 487 624（目标 < 450 000 ✗）。
  已在此如实标注，**不声称达成规划的几何预算**。
- **剩余限制**：若需覆盖真正低端设备，应改为「按档重建几何」或引入真正的 LOD。

### 偏离 #6：剖切采用统一裁剪平面，而非重建可见实例池

- **原规划**：§4.6 允许两种做法，并要求「不能只剖墙面却保留空中的栱」。
- **实际**：对**全部**构件材质施加同一 `THREE.Plane`（`renderer.localClippingEnabled = true`，
  平面法线随相机方位实时更新，始终切掉朝向观众的一半）。
- **影响**：斗栱、瓦、柱、装饰**一并被切**，满足规划要求；代价是切面处呈现壳体断面而非实心剖面。
- **测试**：`04-section.png` 可见内部双圈柱网、暗层斜撑与佛坛。

### 偏离 #7：明层墙面与匾额的形制取自实照（规划未指定）

- **实际**：二层以上为**暗木色板壁 + 直棂窗 / 格子门**；一层檐柱墙为**朱红**；匾额为**白底黑字**
  （而非木底金字）。檐下额枋另加朱红 + 黛绿的彩画带。
- **触发证据**：实拍 `references/photos/view-02.jpg`（一层墙确为朱红、匾额确为白底黑字）。
- **影响**：整体色彩关系与实物一致（此前奶油色墙面使塔体读作现代混凝土建筑）。
- **剩余限制**：色彩为目视比对结果，未经色度仪标定。

### 偏离 #8：浏览器驱动改用自建 CDP 客户端

- **原规划**：§6.1 建议 Playwright/CDP。
- **实际**：用 Node 22+ 内置全局 `WebSocket` 自实现 CDP 客户端（`scripts/cdp.mjs`），**不新增 npm 依赖**。
- **影响**：满足「无需依赖新 CI」且不污染依赖树；功能面小于 Playwright（无自动等待/追踪等）。

### 偏离 #9：帧统计未启动导致 FPS 恒为 0（实现缺陷，已修）

- **触发证据**：首轮 `diagnose` 输出 `samples: 0, fpsMedian: 0`。
- **原因**：`createFrameStats()` 的 `running` 初始为 `false`，而实现中**从未调用 `start()`**。
- **修复**：在渲染循环启动前调用 `frameStats.start()`。
- **测试**：修复后所有档位、场景均得到 59.88 FPS / P95 16.7 ms。

### 偏离 #10：`[hidden]` 属性被作者层 `display` 覆盖（实现缺陷，已修）

- **触发证据**：首轮截图整页被「图形上下文已丢失」遮罩盖住，而 CDP 诊断显示 `ctxOverlayVisible: false`、
  且 `webglcontextlost` **从未触发**。
- **原因**：`.yx-overlay / .yx-modal / .yx-floors / .yx-hotspots` 设了 `display: grid|flex`，
  优先级高于 UA 样式表的 `[hidden]{display:none}`，于是所有遮罩与弹窗**始终显示**并盖住页面。
- **修复**：新增全局兜底 `[hidden] { display: none !important; }`。
- **影响**：这是**误判为「WebGL 上下文丢失」的假故障**；真实问题是 CSS 优先级。

### 偏离 #11：Chrome 进程未随脚本退出（影响验收稳定性）

- **触发证据**：连续两轮验收之间出现 `Inspected target navigated or closed (-32000)`（渲染进程崩溃）。
- **原因**：`process.exit()` 不会终止 spawn 出来的 Chrome 子进程，残留实例持续占用 GPU 与 WebGL 上下文。
- **修复**：Chrome 以 `detached: true` 启动，关闭时 `process.kill(-pid)` 杀整个进程组。

### 偏离 #12：画布尺寸被 inline style 冻结（实现缺陷，已修）

- **触发证据**：390×844 视口下截图里塔体被切在画面右侧，`getBoundingClientRect()` 显示
  `canvas` 的 CSS 尺寸仍是 **1200×713**（首次桌面布局的值），而绘图缓冲已是 390×844。
- **原因**：`createStage` 里首次调用 `renderer.setSize(w, h)` **未传 `updateStyle = false`**，
  three.js 因此把 `canvas.style.width/height` 写成固定 px 的**内联样式**，
  内联样式优先级高于样式表里的 `.yx-canvas { width:100%; height:100% }`，
  画布尺寸就此冻结在首次布局值上。
- **修复**：所有 `setSize` 调用统一传 `updateStyle = false`（由样式表负责尺寸），
  并给 `.yx-canvas` 的 `width/height` 加 `!important` 兜底。
- **影响**：这是**竖屏取景完全错误**的根因；修复后画布尺寸与视口严格一致
  （实测 1200×800 → `canvasCss [1200,800]`；390×844 → `canvasCss [390,844]`）。

### 偏离 #13：竖屏自动取景（新增能力，规划未涉及）

- **原规划**：§4.6 只给 `fitDistance = (radius / sin(fov/2)) × 1.18`，未考虑竖屏。
- **实际**：改为**拟合盒**（宽 30.6 m = 塔身底径 ×1.01，高 67.31 m = 通高），
  取 `max(垂直所需距离, 水平所需距离) × 1.06`；相机**沿当前朝向**后拉，不改变视角方向。
  刻意**不把宽大的台基计入拟合盒**，否则竖屏时塔体会被压得很小。
  用户手动缩放后不再自动干预。
- **影响**：竖屏也能完整看到塔体，且台基在极窄屏上允许轻微出血。

### 偏离 #14：窄屏 UI 布局重做

- **原规划**：§3.1 要求窄屏「顶部标题淡化压缩到两行，底部可左右滑动的操作条，
  点热点出现可关闭下拉信息抽屉（max 45vh），小于 360px 折叠为『探索』，保证 Canvas 至少占高 55%」。
- **实际**：标题压为两行并加渐变底衬保证可读；模式条与控制条各占一行、均可横向滑动；
  楼层与热点列表改为横向可滑动的两行（原为竖排压在画面中部）；
  调试 HUD 在窄屏隐藏；抽屉最大高度 52vh。
- **触发证据**：首版 390×844 截图中标题占三行、热点/楼层竖排压在画面中部、控制条折成两行挤占画面。
- **剩余限制**：「小于 360px 折叠为『探索』」的极窄屏折叠菜单**未实现**，
  320×640 下仍显示完整按钮行（可横向滑动，不遮挡 Canvas）——**记为未完全实现**。

### 规划显著优于本机初版简报之处（采信规划，未回改）

- **「54 是斗栱『种』不是『54 朵』」**：本机初版简报把它列为「来源冲突待裁决」；规划引 H03 原始 PDF
  确认为「54 种、480 朵」，并要求模型台账与文献数字**并列陈述**。本机据此改写了「细节密度」验收口径。
- **测量口径纪律**：规划要求每个数值带 `measurementDatum`，禁止把 67.31 / 30.27 当作现状实测。
  本机据此把全部 43 条尺寸拆成 `valueM / estimateM / certainty / measurementDatum / sourceIds`。
- **台账机制**：规划要求「先建审计清单，再生成实例」，本机原无此机制，已按 `bracketTypeId` +
  `ledger` 实现，并以 `summarizeBrackets()` 输出。

## 9. 斗栱台账与文献数字的差异解释

| 项 | 数值 | 来源 |
|---|---|---|
| 斗栱形制种类 | **54 种** | 2018 年中国土木工程学会《空间结构简讯》原始 PDF（H03） |
| 朵数（文献统计口径） | **480 朵** | 同上 |
| 本模型铺作实例总数 | **352 套** | 台账实算（`reports/bracket-ledger.json`） |
| 本模型几何类别数 | **33 类** | 台账实算（按 `floor × ring × positionKind × sectionKind × variant` 归并） |
| 逐层实例数 | 一层 96（外檐 32 / 内槽 32 / 副阶 32）、二至五层各 64（外檐 32 / 内槽 32） | 台账实算 |

**差异原因（不回避）**：
1. **统计对象不同**。文献的「480 朵」统计的是**实物的斗栱朵数**（含转角、补间、不同位置的全部实例）；
   本模型的 352 是**按铺作组生成的实例数**，每组同时含栌斗、泥道栱、华栱、散斗、令栱、昂、耍头等**多个分件**。
   两者的计数单位不同，不可直接相减。
2. **转角计法不同**。本模型把每个角柱按**相邻两面各布一套**（8 角 × 2 = 16 套），
   而一件实物转角铺作是**一套复合构件**，文献计数通常按一套计。
3. **未取得逐层 480 朵的实测位置表**（H05 图表为图片、本轮未逐格识读；H06 清华论文全文未取得）。
   按规划要求，**不宣称精确重现 480 朵**，在 UI 与报告中并列陈述文献口径与模型台账。
